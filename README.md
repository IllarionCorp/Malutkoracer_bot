# Бронирование гоночного трека

Telegram-бот на Python. Администратор задаёт дату, окно доступного времени, цену часа и число автомобилей, которые могут одновременно находиться на треке. Пользователь выбирает время начала, количество часов, вводит госномер и подтверждает рассчитанную сумму. В общем расписании доступны оставшиеся места и участники.

## Запуск в Windows

Виртуальное окружение `.venv` уже создано. Команды ниже используют его Python напрямую.

1. При необходимости установи зависимости:

   ```powershell
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt
   ```

2. Создай бота через [@BotFather](https://t.me/BotFather), команда `/newbot`.
3. Открой `.env` в корне проекта и заполни `BOT_TOKEN` и `DATABASE_URL`. Если файла нет, скопируй `.env.example` в `.env`. Перед запуском бота запусти PostgreSQL по инструкции ниже.
4. Запусти:

   ```powershell
   .\.venv\Scripts\python.exe -m booking_bot
   ```

5. Напиши боту `/id`. Добавь полученное число в `ADMIN_IDS` в `.env`. Несколько ID разделяются запятыми.
6. Останови процесс сочетанием `Ctrl+C`, запусти снова и отправь `/admin`.

Для получения уведомлений каждому администратору нужно сначала открыть личный чат с ботом и отправить `/start`. Изменения `.env` применяются после перезапуска.

## PostgreSQL

Бот использует PostgreSQL через [Psycopg 3](https://www.psycopg.org/psycopg3/docs/). База должна существовать; таблицы и индексы создаются при запуске автоматически. Пользователю базы нужны права на создание таблиц в выбранной схеме.

Для локального запуска с установленным Docker Desktop:

```powershell
docker compose up -d --wait postgres
```

В `.env` укажи:

```dotenv
DATABASE_URL=postgresql://booking_bot:booking_bot@localhost:5432/booking_bot
```

Эти параметры совпадают с `compose.yaml`: PostgreSQL доступен на `localhost:5432`, данные хранятся в Docker volume `postgres_data` и сохраняются при `docker compose down`. Удаление volume удаляет базу. Для другой установки PostgreSQL укажи её пользователя, пароль, адрес и имя базы. Спецсимволы в имени пользователя и пароле URL нужно кодировать. При смене `POSTGRES_PASSWORD` или `POSTGRES_PORT` для Docker обнови и `DATABASE_URL`; пароль применяется при создании нового volume.

Если данные уже были в SQLite, останови бота и выполни однократный перенос в пустую PostgreSQL:

```powershell
.\.venv\Scripts\python.exe -m booking_bot --migrate-sqlite data/bookings.sqlite3
```

Переносятся все окна, активные и отменённые брони, ID, цены, вместимость, правила и ссылка на проезд. Для старых окон без поля вместимости сохраняется одно место. Перенос выполняется одной транзакцией; при ошибке записи откатываются. Повторный импорт в непустую базу отклоняется. Исходный файл SQLite остаётся без изменений. После переноса бот работает только с PostgreSQL; `DATABASE_PATH` больше не используется.

## Как открыть запись

Администратор отправляет `/addslot` или нажимает «Добавить окно записи» в `/admin`. Бот последовательно запрашивает:

1. Дату в формате `ДД.ММ.ГГГГ`.
2. Время начала и окончания, например `10:00-20:00`.
3. Стоимость часа в рублях, например `2500` или `2500,50`.
4. Число автомобилей, которые могут одновременно быть на треке: целое число от `1` до `1000`.
5. Подтверждение открытия записи.

Время трактуется в часовом поясе `TIMEZONE`, по умолчанию `Europe/Moscow`. Окончание `24:00` обозначает полночь следующего дня. Окно должно начинаться в будущем и длиться хотя бы час. Открытые окна не могут пересекаться.

Начала сеансов идут с шагом в час от начала окна: для окна `10:30-15:30` это `10:30`, `11:30` и далее. Бронирование занимает целое число часов и полностью помещается в одно окно. Неполный час в конце окна для записи не используется.

`/slots` показывает окна и позволяет закрыть их для новых записей. Ранее созданные брони сохраняются. Чтобы изменить тариф или расписание, закрой окно и создай новое. Сумма существующих броней останется прежней.

## Как бронирует пользователь

`/book` → дата → окно с тарифом → время начала → количество часов → госномер → проверка суммы → подтверждение.

Например, при цене `2500 ₽/ч` и длительности `3 ч` итог равен `7500 ₽`. Деньги рассчитываются в целых копейках, без ошибок округления `float`. Бот рассчитывает сумму к оплате; приём платежей в эту версию не входит.

Каждая бронь занимает одно место для автомобиля на выбранное количество часов. Число одновременно действующих броней ограничено вместимостью окна. При одновременных запросах проверка и сохранение выполняются в одной транзакции PostgreSQL с блокировкой таблиц расписания и броней, чтобы лимит не был превышен. Чтение расписания при этом остаётся доступным. Соседние брони, например `10:00-12:00` и `12:00-14:00`, используют место по очереди. Пока пользователь вводит госномер и проверяет сумму, место ещё не удерживается: доступность повторно проверяется при подтверждении.

Кнопки времени показывают остаток на первый час. При выборе длительности отображается число мест, свободных на весь выбранный интервал. Например, если на первый час свободно 3 места, а на второй — 1, для брони на 2 часа доступно 1 место.

## Свободные места и участники

Каждому пользователю доступны кнопка «Места и участники» в главном меню и команда `/schedule`. Выбери дату и окно записи. Бот покажет:

- оставшееся число мест для каждого часа, например `10:00–11:00: осталось 3 из 5`;
- ники записавшихся, длительность и время их брони, например `@racer — 3 ч`;
- имя из Telegram с пометкой «без username», если у участника нет ника.

Список участников разбит на страницы. Кнопка «Обновить» заново получает остаток мест и записи. Отменённые брони исчезают из списка и освобождают место. Полностью занятые окна остаются доступными для просмотра. Закрытые администратором окна с предстоящими бронями также видны, но запись в них не принимается.

В общем списке не показываются госномера, числовые Telegram ID и суммы чужих броней. Ники берутся из данных Telegram на момент создания брони.

Чтобы задать другую вместимость, закрой старое окно через `/slots` и добавь новое. Существующие брони учитываются при подсчёте мест нового окна, если время пересекается.

`/my` показывает свои предстоящие и текущие брони. Отмена требует подтверждения и доступна владельцу до начала сеанса. Администраторы получают уведомления о создании и отмене, а в `/admin` видят все записи с госномерами, суммами и данными клиента из Telegram.

`/cancel` прерывает текущий ввод. Черновик действует 15 минут и сбрасывается после перезапуска; подтверждённые брони остаются в PostgreSQL.

## Правила и схема проезда

В главном меню доступны кнопки «Правила» и «Схема проезда». Также можно отправить `/rules` и `/directions`.

Администратор заполняет информацию в личном чате с ботом:

1. Отправь `/admin` и нажми «Изменить правила».
2. Отправь правила одним текстовым сообщением, до 3500 символов. Они сохранятся сразу.
3. Вернись в `/admin` и нажми «Изменить схему проезда».
4. В Яндекс Картах открой трек или нужный маршрут, выбери «Поделиться» и скопируй ссылку. Отправь её боту одним сообщением. Подробнее — в [инструкции Яндекса](https://www.yandex.ru/support/maps/ru/concept/get-map-reference).

Пользователь увидит текст правил и кнопку «Открыть Яндекс Карты» со ссылкой администратора. Пока информация не заполнена, бот сообщает, что она ещё не опубликована. `/cancel` отменяет редактирование, сохраняя прежние данные.

Правила и ссылка сохраняются в PostgreSQL и остаются после перезапуска. Новые изменения доступны пользователям сразу, без перезапуска бота. Данные редактируются только администраторами из `ADMIN_IDS`.

## Настройки и данные

| Настройка | Назначение |
| --- | --- |
| `BOT_TOKEN` | Токен от BotFather |
| `TRACK_NAME` | Название трека в сообщениях |
| `TIMEZONE` | Часовой пояс расписания |
| `ADMIN_IDS` | Числовые Telegram ID администраторов |
| `DATABASE_URL` | Обязательная строка подключения к PostgreSQL: `postgresql://user:password@host:5432/database` |
| `MAX_BOOKING_HOURS` | Максимальная длительность одной брони, по умолчанию 24 |
| `BOOKING_DAYS` | На сколько дней вперёд администратор может открыть окно, по умолчанию 365 |
| `MIN_NOTICE_MINUTES` | Минимальный запас времени до начала брони, по умолчанию 0 |

Расписание и брони сохраняются в PostgreSQL. Для резервной копии используй `pg_dump`, для восстановления — `pg_restore`. `.env`, `.venv` и прежняя папка `data` исключены из Git через `.gitignore`. Токен и строку подключения вписывай в локальный `.env`.

Для работы боту нужен постоянно запущенный процесс с доступом к Telegram. Используется long polling: публичный сайт и webhook не требуются. На один токен запускается один процесс бота.

## Проверки без Telegram

```powershell
.\.venv\Scripts\python.exe -m booking_bot --check
$env:TEST_DATABASE_URL = 'postgresql://booking_bot:booking_bot@localhost:5432/booking_bot'
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

`--check` проверяет настройки, подключение и создание таблиц без обращения к Telegram. Для интеграционных тестов нужен работающий PostgreSQL и явно заданный `TEST_DATABASE_URL`: каждый тест создаёт отдельную случайную схему и удаляет её после выполнения. Пользователю нужны права `CREATE` на базу. Таблицы рабочей схемы не изменяются. Без `TEST_DATABASE_URL` интеграционные тесты пропускаются; тесты настроек выполняются отдельно без PostgreSQL.

Тесты подменяют отправку сообщений и проверяют расчёт суммы, большие Telegram ID и цены, лимит автомобилей и одновременные запросы, повторное подтверждение, отмену чужой брони, права администратора, перенос старой SQLite, остаток мест и публичный список участников, а также полный сценарий записи.

Документация: [python-telegram-bot](https://docs.python-telegram-bot.org/en/stable/), [Telegram Bot API](https://core.telegram.org/bots/api).
